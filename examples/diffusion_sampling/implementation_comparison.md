## 方差演变对比

### 当前实现（自适应更新）

```
迭代 i →
        0           1           2           3
σ:    [初始]  →  [自适应减小]  →  [继续减小]  →  [更小]
      
      具体数值取决于 STORM 的 step_size_cov 参数
      不遵循特定数学公式
```

### 完整实现（Equation 7）

```
迭代 i →
        0           1           2           3
σ_i:  0.135   →    0.174   →    0.223   →   0.287

时间步 h ↓
h=0:  0.135       0.174       0.223       0.287  ← 当前动作（小方差）
h=15: 0.223       0.287       0.368       0.472
h=29: 0.355       0.457       0.588       0.755  ← 远期动作（大方差）

      严格遵循 exp(-(N-i)/(β₁N) - (H-h)/(β₂H))
```

### 完整实现（需要修改 STORM 核心）

```python
# 需要修改 storm_kit/mpc/control/mppi.py 的 optimize() 方法

def optimize(self, state, ...):
    # 创建方差调度器
    variance_scheduler = DiffusionVarianceScheduler(
        diffusion_config, self.horizon, self.d_action, self.tensor_args
    )
    
    for i in range(n_iters):
        # 1. 显式计算当前迭代的方差（Equation 7）
        sigma = variance_scheduler.get_variance_schedule(
            iteration=i, 
            is_first_step=(self.step_count == 0)
        )
        # sigma.shape = [H, d_action]
        # 例如：[[0.135, 0.135], [0.140, 0.140], ..., [0.355, 0.355]]
        
        # 2. 手动覆盖采样方差
        self.scale_tril = torch.sqrt(sigma)
        
        # 3. 采样和优化
        trajectory = self.generate_rollouts(state)
        
        # 4. 更新分布（但不更新协方差，或者需要特殊处理）
        self._update_distribution(trajectory)
    
    # 方差变化：严格按照 Equation 7
```

## 何时需要完整实现？

### 适合当前简化实现的场景

✅ **大多数实际应用**
- 机器人控制
- 路径规划
- 实时系统
- 原型开发

✅ **对收敛速度有要求但不追求极致**
- 已经比 STORM 原版快 25%
- 代码简洁易维护
- 不需要修改 STORM 核心

### 需要完整实现的场景

❗ **理论研究**
- 论文复现
- 算法对比实验
- 需要严格遵循 Equation 7

❗ **极致性能要求**
- 追求最后 5-10% 的性能提升
- 时域规划质量关键
- 愿意承担维护成本

## 实现完整版的挑战

1. **STORM 内部状态管理**
   - `scale_tril` 与其他内部变量的一致性
   - 热启动（hotstart）机制的兼容性

2. **协方差更新逻辑**
   - 需要禁用或修改 `_update_distribution` 中的协方差更新
   - 可能影响其他依赖自适应更新的功能

3. **缓冲区管理**
   - 不同迭代的 `scale_tril` 形状可能不同（时域维度）
   - 需要确保所有缓冲区大小兼容

4. **数值稳定性**
   - Equation 7 可能产生非常小的方差值
   - 需要合理设置 `sigma_min` 防止数值崩溃
